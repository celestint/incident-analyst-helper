

**版本**：v0.1.0 

**定位**：一个可本地运行的排障分析助手。告警进来后，运维人员手动触发，助手按预设的排障手册逐步收集证据，实时展示分析过程，最后给出原因、证据和修复建议。报告只读归档，不重复分析。


## 1. 目标用户

- **运维人员**：看告警、触发分析、看技术报告。
- **业务用户**（P1）：提交问题、看业务影响和恢复时间。

## 2. 核心场景

**运维**：告警列表 → 点击“分析” → 实时看到每一步 → 得到报告 → 之后随时回看，不重跑。
**业务**（P1）：提交问题如“支付打不开” → 系统关联告警 → 看到业务语言的状态和恢复时间。

## 3. MVP 范围（P0）

只做运维视角闭环，不做用户视角。

**主流程与功能关联**
1. **告警进入列表**  
   系统接收模拟告警，自动存入告警列表，状态为“待分析”。列表展示名称、级别、服务、时间、状态和操作按钮。运维人员可以浏览。
2. **手动触发分析**  
   运维人员点击“分析”按钮。系统校验状态（仅“待分析”或“失败”可触发），然后将状态改为“分析中”，开始执行。分析中或已完成的告警不可再次触发，防止重复。
3. **按手册执行并实时展示**  
   系统根据告警名关键词匹配排障手册，未命中时回退兜底手册：
   - **匹配到专用手册（Runbook 模式）**
   Agent 按手册定义的步骤顺序执行，每步调用工具收集指标、日志、trace 等证据。前端用一条时间线展示全过程，每个节点包含“实际执行动作”和“对应手册步骤”，例如“执行手册第 1 步：查询 CPU 指标 → 工具：查询 CPU 指标 → 结果：CPU 95% → 状态：已完成”。顶部用进度条展示手册整体进度（如“3/4 步已完成”）。
   - **未匹配到手册（兜底手册模式）**
   回退到通用兜底手册 Fallback.md，同样严格按固定步骤（指标 → 日志 → 调用链）顺序执行，禁止自由规划排查路径。兜底手册额外包含：第 0 步告警名价值判断（测试/演示等无语义告警名跳过工具调用直接出报告）、双窗口策略（告警窗口查空补查前 30 分钟基线窗口，双空不下结论）。
   两种情况共用同一条时间线和同一套 SSE 事件类型，前端按事件类型渲染不同节点。用户只需看这一条时间线，就能知道 Agent 做了什么、为什么这么做、拿到了什么结果、结论是什么。
   （原设想的“探索模式”——LLM 自拟排查计划并逐步反思调整——未实现，作为后续设想保留。）
4. **生成报告并归档**  
   分析完成后，系统生成技术报告，包括可能原因、助手对每个原因的可信度（把握程度）、每条推荐操作的风险等级（低/中/高）、推荐操作和证据链。报告以只读形式保存，状态改为“已完成”。再次查看时直接加载已有报告，不重新分析。
5. **失败重试与历史回看**  
   如果分析失败，状态为“失败”，可以点击“重试”重新启动。已完成的分析记录直接在告警总览页列表中展示，点击 “查看报告” 即可加载只读报告。

**验收**：发一条告警 → 点分析 → 实时看到每一步 → 得到报告 → 再次查看直接展示，不重跑。
## 4. 后续版本

**P1：分两类用户分别增强**
**给业务用户用的（用户视角）**
- **用户问题功能**：业务用户提交问题 → 系统关联告警 → 自动生成业务摘要 → 用户在问题页看到业务语言的状态、影响范围和恢复时间。整个过程只显示业务语言，不显示技术细节。

**给运维人员用的（运维体验增强）**
- **指标曲线**：在分析页里把 CPU、内存等数据画成图，辅助判断异常。
- **筛选与导出**：告警多了可以按服务、时间筛选，报告可以导出成 PDF。

**P2：让系统更自动、更智能、能接真实数据**
- **告警聚合**：同一时间、同一服务的多条告警合并为一个事件组，只分析一次。列表默认展示事件组，**组内可展开查看原始告警，原始告警不会消失**。
- **告警抑制**：高优先级告警触发后，由它引起的低优先级告警不再单独分析。**被抑制的告警不单独展示，但合并到触发抑制的高优先级告警下，用户展开即可看到**。
- **知识库**：让助手能查历史案例和文档。
- **真实数据源**：从真实的监控和日志系统拿数据，替换模拟数据。
- **多助手协作**：分类、调查、决策等不同 AI 助手分工合作。

## 5. 关键页面

| 页面        | 面向     | 内容                                                                                                                                         |
| --------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **告警总览**  | 运维     | 列表默认展示所有告警（含待分析、分析中、已完成、失败），已完成记录直接显示在列表中，点击 [查看报告] 即可加载只读报告，无需先筛选。顶部提供可选的状态筛选栏，仅用于告警数量多时缩小范围。每条告警按状态显示对应按钮：[分析] / [查看进度] / [查看报告] / [重试]。 |
| **分析页**   | 运维     | 单条时间线（每个节点同时包含“实际执行动作”和“对应手册步骤”）、顶部手册进度条、底部只读报告。                                                                                           |
| **用户问题页** | 业务（P1） | 业务用户提交问题 → 系统关联告警 → 自动生成业务摘要 → 用户查看业务语言的状态、影响范围和恢复时间。只显示业务语言，不显示技术细节。                                                                      |

**告警总览页是运维唯一入口**：所有告警都在这里，已完成记录直接可见，点击 [查看报告] 即可回看，筛选可选。  
**分析页是核心**：用户能看到助手在做什么、对应手册哪一步、拿到了什么证据、结论是什么。  
**用户问题页是 P1 功能**：让业务用户也能理解故障影响，与运维视角共享同一个事件，但只展示业务语言。

## 6. 非功能需求

- **安全**：只读诊断，不执行修复；模拟数据无敏感信息；用户视角不返回技术细节。
- **可用**：失败可重试；断线可恢复；无 AI 时可按手册出基础报告。
- **可扩展**：新增故障场景只需加手册和模拟数据。


## 7. 里程碑

| 阶段     | 内容                                                              |
| ------ | --------------------------------------------------------------- |
| MVP    | 运维闭环：告警、触发、实时分析、报告归档、通过告警总览直接回看                                 |
| **P1** | 用户视角：用户问题功能（业务用户提交问题 → 系统关联告警 → 生成业务摘要 → 用户查看业务语言的状态、影响范围和恢复时间） |
| **P2** | 告警聚合与抑制、知识库、真实数据源、多助手协作                                         |

## 8. 主要风险

- 模拟数据与真实场景有差距 → 聚焦单一场景，明确边界。
- 用户视角业务语言不准 → 可用先用固定话术，再引入 AI 生成更灵活的摘要。
- 个人精力有限 → 严格按 P0 迭代，不做多余功能。

**一句话总结**：MVP 只做一件事——让运维人员点一下，就能实时看到助手按手册排查，最后拿到一份只读报告。回看直接在同一个列表里点 “查看报告” 即可，筛选可选。
